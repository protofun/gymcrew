# GymCrew Screen Inventory

Generated by the Phase 0 discovery audit for the Reacticx migration (see `GYMCREW_REACTICX_MIGRATION.md`). Every route under `src/app/` was read in full. Fields follow AGENTS.md §4. "NOT VERIFIED" markers are used where a claim couldn't be confirmed by reading code (per AGENTS.md §37 — no fake completion).

Legend for compact columns: **Loading / Empty / Error** — `-` means none found in the file.

---

## Navigation overview

- **Root gate** (`src/app/index.tsx`): signed out → `/onboarding`; signed in → `getPostAuthRedirect()` (onboarding-store + Clerk `unsafeMetadata`, reconciled via `useClerkFlagSync`) routes to the onboarding wizard, crew selection, or `/home`.
- **`(auth)`**: no layout-level redirect (moved into each screen after a past bug where `/sign-up` silently reused an active session).
- **`onboarding`**: linear wizard enforced by each screen's own `router.push`, not file order. Layout redirects out if already onboarded/crew-selected.
- **`(tabs)`**: main authenticated shell (home/crew/log/ranks/profile). On mount runs `Promise.all` over ~28 store `syncFromServer()` calls, then `flushLocalStateToServer()`, sets `hasSyncedOnce`, registers push notifications, auto-starts the app tour on first run.
- **`profile/*`, `notifications/*`, `workout/*`, `workout-split/*`, `ranks/*`, `crew/*`, `nutrition/*`**: auth-gated detail stacks pushed from the tabs.
- **`legal/*`**: deliberately ungated (reachable signed in or out).
- **`build-crew/*`**: multi-layered gate with 3 "already done this" escape hatches (Clerk metadata, Founding Athlete backend link).

**Workout logging performance finding (critical):** `active.tsx` renders all exercises in a plain `ScrollView` (no virtualization). `ExerciseSetRow` fires `onUpdate` on every keystroke. `active-workout-store.ts`'s `updateSet` (and nearly every mutator) unconditionally calls `syncPush`, which POSTs the **entire workout state** to the backend on every keystroke, fire-and-forget, unthrottled. Not blocking UI, but a real scalability concern — preserve behavior but plan to debounce/diff in the rewrite.

Migration risk: if the new design wants "drag directly on the photo," this needs a different implementation, not a restyle; fixed 420px height, exactly 2 photos.

## Cross-cutting findings for the whole app

1. **Unthrottled per-keystroke full-state backend sync** (`lib/backend-sync.ts`) — the single most important performance finding, centered on workout logging but structurally present in every store mutator.
2. **Hand-rolled SVG line charts duplicated 2-3×** (`RankProgressionChart` in whats-my-rank.tsx, `ProgressionChart` in [liftId]/compare.tsx) — consolidate into one shared chart component.
3. **`Alert.alert` vs `ConfirmModal` inconsistency** — `workout/active.tsx` explicitly avoids `Alert.alert` (multi-button alerts silently no-op on RN Web) but `workout/build.tsx`, `nutrition/meal/[id].tsx`, `nutrition/my-foods.tsx`, `nutrition/my-meals.tsx`, `build-crew/discover.tsx` still use it — audit needed.
4. **"Known 9-lift card vs generic 800+-exercise proxy" branching** duplicated across `whats-my-rank.tsx`, `ranks/history.tsx`, `ranks/[liftId]/index.tsx` — shared helper candidate.
5. **Loading/empty/error conflated**: `crew/leaderboard.tsx`, `build-crew/discover.tsx`, `progress-photos/compare.tsx`, `ranks/history.tsx` all silently turn fetch errors into "empty" — decide on a consistent 3-state pattern for the redesign.
6. **Camera permission-gate UI duplicated** (`PhotoCaptureGuide`, `nutrition/scan-barcode.tsx`) — shared `CameraPermissionGate` component candidate.
7. **Skia confetti is native-only** (`react-native-fast-confetti` via `BadgeRevealFx`/`DivisionUpOverlay`) — no web CanvasKit wiring, a web-parity gap.
8. **`ranks/build-your-graph.tsx`** is dev-only tooling styled identically to the real screen — confirm migration scope with the product owner.
9. **`EditableText`** (32 usages, the most-reused component) is a live dev-mode content-override wrapper around text — must be preserved functionally, not just replaced with plain `Text`.
10. Duel/War/League UI is scattered across `(tabs)/crew.tsx` (main live views) and `crew/*` detail screens — treat as one feature area during planning, not per-directory.
