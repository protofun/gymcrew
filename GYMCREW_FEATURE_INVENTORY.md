# GymCrew Feature Inventory

Generated by the Phase 0 discovery audit. Every feature below was verified against actual code (stores, `lib/`, `data/`, and screens) per AGENTS.md §5 — nothing here is assumed from the feature list in AGENTS.md alone.

## Authentication
**Verified.** Clerk-based (`@clerk/expo`). Email/password + Google/Facebook/Apple SSO, device-trust 2nd-factor email codes, password reset, one-time-ticket deep-link sign-in ("Founding Athlete" flow), OAuth callback handling. Backend independently verifies Clerk JWTs by hand (RS256, JWKS cached hourly) rather than trusting the client. Screens: `(auth)/*`.

## Onboarding
**Verified.** ~12-screen linear wizard (intro → welcome → personal info → stats → goal → experience → metrics → rank reveal → workout preferences → schedule → notifications → all-set), then crew selection (`build-crew/*`, own 5-8 screen sub-wizard). State lives in `onboarding-store` (71 file usages — the most depended-on store in the app) and is dual-written to Clerk `unsafeMetadata` for self-healing cross-device completion detection.

## Profile
**Verified.** Edit personal info, units (kg/lbs), notification preferences with time pickers, subscription status (read-only), account management (password/delete/sign-out), Dev Mode + Admin Challenges (email-gated), PR achievements timeline, training history, body log (weight/BMI), rank history, all-stats dump, workout split editor, rewards/store (spend tokens), blocked users, roadmap, changelog, support tickets. Screens: `profile/*`.

## Home
**Verified.** Dashboard combining: announcement banner, greeting widget, crew war widget, visual training calendar, muscle suggestions (weakest-muscle nudge), "biggest opportunity" card, last-workout widget, nutrition summary widget, goals widget, crew card. Screen: `(tabs)/home.tsx`.

## Workout logging
**Verified — core feature.** Add/replace/remove exercises, log weight/reps/sets with a warm-up flag, auto-starting rest timer, discard/finish flows. Finishing computes PR detection, volume, XP, streak update, challenge contributions, Crew War attack (fire-and-forget), crew-feed events, and reschedules notifications — all in `workout/active.tsx`'s `handleFinish()`. **Performance note**: every keystroke triggers a full-state fire-and-forget sync to the backend (`lib/backend-sync.ts`) — functional today, flagged for debounce/diff in the rewrite. Screens: `workout/*`.

## Workout planner / custom workouts
**Verified.** Save/edit/delete custom workout templates (`custom-workouts-store`), 15 built-in day templates (`data/workout-templates.ts`) mapped from 20 named training-split programs (`data/training-splits.ts`), backfill logging for past dates (explicitly excluded from XP/streak/PR/War). Screens: `workout/build.tsx`, `workout/templates.tsx`, `(tabs)/log.tsx`.

## Exercise selection / library
**Verified.** 873 exercises from the public-domain free-exercise-db (`data/exercises.json`), custom user-created exercises, favorites, exercise instructions with muscle diagrams (`ExerciseInstructionsModal` + `MuscleGroupPicker`). Component: `ExercisePickerModal` (used in 7 places).

## Sets/reps/weight logging
**Verified.** `ExerciseSetRow` — two numeric inputs (weight/reps), warm-up toggle, complete-checkmark; collapses to a compact read-only row once completed (deliberate perf/UX choice).

## Workout completion
**Verified.** `workout/summary.tsx` — multi-tab report (Overview/Exercises/Muscles/PRs), share-as-image, notes. Dual-purpose (just-finished hero + evergreen detail view, a former separate screen folded in).

## PR detection
**Verified.** `lib/workout-finish.ts` `checkPersonalRecords()`, `personal-records-store` (per-exercise heaviest set ever, pending-sync tracking for offline resilience). Anti-cheat plausibility gate (`lib/rank-plausibility.ts`) before a lift can be logged as a PR outside a real workout.

## Rankings — the app's core identity
**Verified.** 15-tier fair-ranking system (`lib/rank.ts`): normalizes lift by bodyweight ratio, gendered strength-standard tables for 4 major lifts, age-grading multiplier, maps into 15 tiers. Extended to all 800+ exercises via muscle-group proxy (`lib/generic-lift-rank.ts`). "What's My Rank?" instant wizard, rank simulator (goal projection, weight-needed-for-tier), rank history timeline, gym/global standings.

## Power score
**Verified.** `lib/lift-rank-cards.ts` / `lib/ranks-board.ts` — `ratio × 4000` per lift, auto-curated top-12 achievements across any exercise with a PR. Explicitly documented as the single canonical computation reused everywhere "Overall Power" is shown (Ranks tab, `workout-split/analyze.tsx`, `crew/all-divisions.tsx`) — a cross-screen invariant to preserve exactly.

## Global ranking / Gym ranking / Exercise ranking
**Verified.** 3-way leaderboard (Global players / Gym players / Crews), each scoped within the viewer's own division. Per-exercise standings and head-to-head compare vs crewmates.

## Divisions
**Verified.** Separate 20-tier ladder (Rookie→Apex, `lib/division.ts`) from lift-rank tiers, for both players and crews. XP-required grows ~×1.44/tier. Division-up celebration overlay (`DivisionUpOverlay`, Skia confetti).

## Percentile calculations
**Verified.** Present in `crew/all-divisions.tsx` ("top-percentile note") and rank-detail screens (`ranks/[liftId]/index.tsx`).

## Weak-point engine
**Verified.** `lib/muscle-group-rank.ts` + `lib/rank-simulator.ts` power the "weak-point" flagging (≥4 tiers behind median lift) used in `lift-rank-cards.ts`, the Home "Biggest Opportunity" card, and heavily in the Workout Split generator's priority scoring.

## Arena
**NOT FOUND under this name.** No screen, store, or lib file named "Arena" exists in the codebase. The closest concepts are Crew Wars, Crew Duels, and Crew Leagues (below) — confirm with the product owner whether "Arena" is a planned rename/umbrella for these, or a genuinely unbuilt feature.

## Crew creation / joining
**Verified.** `build-crew/*` wizard — create (name/type/icon, incl. AI-generated avatar) or join (invite code or browse public crews). Backend-created on `crew-ready.tsx` mount; 10-platform invite share grid.

## Crew rankings / Crew members
**Verified.** `crew-store` (31 file usages), full roster with search/filter, role management (leader/co-leader/member via ad hoc string comparison, not an enum), member profiles with muscle-rank heatmap and stats.

## Crew Wars
**Verified.** `crew-war-store`, `lib/war.ts` (attack score = `volume + prCount×250`, mirrored from PHP backend), `CrewWarTab`/`CrewWarWidget` components. Settings toggle for auto-match. Primary live UI lives in `(tabs)/crew.tsx`, not a standalone route.

## Crew Leagues
**Verified.** `crew-league-store`, `lib/crew-league.ts` — weekly standings vs. rival crews (real crew power vs. deterministic-hash-varied simulated rival power), Duolingo-style promotion (top 30%)/relegation (bottom 30%).

## Crew Duels
**Verified.** `crew-duel-store`, 1-on-1 "who does more today" challenges, proposed via `DuelChallengeSheet` on `crew/members.tsx`.

## Crew Challenges
**Verified.** `challenge-store` + `admin-challenge-store`, ~100 procedural weekly templates (`data/challenges.ts`, 3 escalating tiers), custom crew-created battles, admin-curated global challenges. Anti-cheat sanitization in `lib/challenge-progress.ts` (caps weight at 400kg/1.5×PR, reps at 30/set, first 10 sets only).

## "See what everyone's planning to train today"
**Verified.** `today-training-store`, `use-today-workout.ts` hook (resolves manual override > weekly schedule > crew default plan), shown on the Crew tab's Today Plan card.

## Shared crew score
**Verified.** Crew League weekly power + Crew War volume, both real-data-driven (own + fetched crewmate activity), no mock fallback in the computation layer (though `crew/division.tsx`'s rival count still uses stale static mock data — flagged as tech debt).

## Get notified when a crew member hits a PR
**Verified.** `lib/crew-feed.ts` + `crew-feed-store`, real crew-wide PR/streak/division-up feed with unread marker; also surfaces in the Notifications screen.

## "Which muscle groups is the crew neglecting"
**Verified.** `lib/crew-muscle-balance.ts`, `MuscleBalanceCard` component on the Crew tab.

## Live/synchronous crew workouts
**Verified (not in the original feature list, but real and significant).** A member can "lead" a workout that mirrors live to the crew (`led-workout-store`, 15s polling — no websockets, explicit code comment) and others can join it mid-session, seeded from the leader's already-logged exercises.

## Nutrition
**Verified.** Daily diary with meal-slot grouping, date navigation, "copy previous day," calorie/protein/carbs/fat tracking, water tracker, "Goal + Exercise = More Food" calorie add-back mechanic.

## Food logging
**Verified.** Search hub merges local custom foods + paginated Open Food Facts API (de-duplicated by ID), barcode scanning (`expo-camera` + OFF lookup with explicit not-found/error states), quick-add for rough estimates, recent/favorites shortcuts.

## Meals
**Verified.** Shared create/edit screen for both "Meal" and "Shake" (same data shape, `kind` param differs); saved meals list, "log once vs. update saved recipe" branching on quantity edits.

## Saved foods
**Verified.** `custom-foods-store` (user-created foods, full CRUD), `favorite-foods-store`, `off-foods-cache-store` (local memo of seen Open Food Facts products).

## Macros / Calories / Protein / Carbs / Fats
**Verified.** `lib/nutrition-targets.ts` — Mifflin-St Jeor BMR formula × activity multiplier → TDEE, ± goal adjustment (bulk/maintain/cut), protein 1.8-2.2 g/kg by goal, fat 25% of calories, carbs the remainder. Suggested-vs-manual target entry (`nutrition/targets.tsx`).

## Progress (nutrition + body)
**Verified.** `nutrition/progress.tsx` — weight/calorie/protein trend charts with date-range filters, weekly calorie-vs-target bars, macro-split bar, weekly workout/PR stat tiles. Separately, `profile/body-log.tsx` for weight/body-fat/BMI.

## History (workout + nutrition)
**Verified.** `workout/history.tsx` (calendar + list, PR-day badges) and `nutrition/history.tsx` (habit-tracker calendar + 6-month "monthly healthiness" trend — a distinct metric from raw calorie/weight trends).

## Goals
**Verified.** `goals-store` — personal goals (build muscle/strength/endurance/weight), auto-tracked or manual, shown as rings on Home (`GoalsWidget`, `GoalRing`).

## Progress photos
**Verified — high migration risk (see Screen Inventory).** Pose-select (Front/Side/Back) → live camera with a hand-drawn SVG alignment guide → upload → grid of captured photos → pick 2 → before/after reveal-slider comparison. Backend-stored (`progress_photos` table, `backend/uploads/`).

## Settings
**Verified.** Distributed across `profile/*` (units, notifications, account) and `crew/settings.tsx` (crew-level settings) rather than one single settings screen.

## Notifications
**Verified.** Push notifications (`expo-notifications` + custom Expo token registration): daily workout/creatine reminders at user-chosen times, streak-loss nudge, weekly recap, monthly "X% stronger" nudge — all reconciled on every app mount. In-app notification history screen merges real PRs, streak nudges, and crew feed events.

## Support
**Verified.** In-app support ticket system (list/compose/chat-thread detail) backed by the PHP backend, distinct from the Discord/community links mentioned in AGENTS.md's feature list (no direct Discord deep-link found in the audited screens — **NOT VERIFIED** as a distinct feature; only implied via `legal/*` third-party mentions and share-target grids).

## Sharing
**Verified.** Multiple independent share surfaces: workout summary (`WorkoutShareCard`), PR share (`PrShareCard`), crew invite (10-platform `SHARE_TARGETS` grid with mixed deep-link/native-share fallback), progress-photo comparisons are not directly shareable (**NOT VERIFIED** — no share action found on `progress-photos/compare.tsx`).

## App tour / onboarding spotlight
**Verified (not in the original list, but real).** `AppTourOverlay` — mascot-narrated first-run spotlight tour across Home/Ranks/Crew/Profile (`react-native-spotlight-tour`), replayable from `profile/account.tsx`.

## Developer Mode / Admin tooling
**Verified (not in the original list, but real and load-bearing for content ops).** Email-gated (`jaimy.mathon@gmail.com` and others) Dev Mode unlocks: `EditableText` in-app copy overrides (32 call sites app-wide), a fake muscle-rank sandbox (`ranks/build-your-graph.tsx`) for marketing screenshots, and Admin Challenges CRUD. **Recommend confirming with the product owner which of these (if any) should be carried into the migrated app** — some are explicitly marketing/screenshot tooling, not user-facing product.

## Monetization / paid tier
**NOT VERIFIED as implemented.** `profile/subscription.tsx` is read-only copy explaining the paid tier; no in-app purchase flow, App Store/Play Store billing integration, or server-side entitlement gating was found in the audited code. `crew-store.subscriptionActive` exists as a flag but its write path (an actual payment) wasn't located in this pass — flag for a dedicated payments audit before the migration assumes this feature is real.
